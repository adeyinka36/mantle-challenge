The original checkout method did the whole job. It read the request, found or created the customer, worked out the price, saved the order, sent the email and wrote the log. A new customer type meant another branch in that method, and so did a new message. The sample and gift behaviour had been added in the same way. The pricing rules could not be tested on their own, because the only way to run them was through the controller, with a database and a mailer.

PlaceOrder now finds the customer, asks OrderFactory for the order, saves it, dispatches OrderPlaced and returns the id and total. The controller maps the JSON onto PlaceOrderData and returns that result. Validation sits on the DTO. An empty cart or a bad email is a 422. A body that is not JSON is a 400.

Each discount is its own class. PriceCalculator uses the first tagged rule that matches. A free sample is one of those rules, with a higher priority, so a sample stays free for every customer type, including when it is also a gift. Customer types are a backed enum, stored in the same string column as before. A missing type still defaults to regular. An unknown type such as wholesale never becomes an enum, so the serializer rejects it before the choice constraint runs. The error text is the framework one, which is a bit clumsy. I left that message as Symfony writes it.

Gift wrap is 3.50 from GIFT_WRAP_PRICE. OrderFactory adds it after the discount and before the order is saved. I treated wrap as part of building the order, so the discount classes stay discounts only. The old charge was the discounted total plus the wrap, and the ticket was a bit loose about whether wrap came before or after the discount. I kept the old reading, so a 25 pound VIP gift is saved as 23.50. A sample does not get wrap. The purchaser still gets the normal priced confirmation. The recipient gets a separate note with the subject "A gift for you" and the text "A gift is on its way to you." The ticket asked for a message with no prices and did not give the words, so I used a short sentence that contains none.

The trade rule is still 10 percent off and then 5 pounds, which can go below zero. The saved total is floored at 0 after that discount and after any gift wrap. A 5 pound trade order is saved as 0.00. A 5 pound trade gift is saved as 3.00, because the wrap is added and then the floor is applied. A 25 pound trade order stays 17.50.

SMS was already a listener once mail and the log had moved out of the action. SendOrderSms texts the same confirmation as the purchaser email when a mobile is present, and sends nothing when the number is missing or blank. SmsSender is how the code talks to a provider. NullSmsSender is what the app boots with, so there is no real gateway. Tests use a recording sender.

Most tests build the objects themselves and do not boot the kernel. Two HTTP tests do boot it. One places a VIP gift order, to check that the container really wires the discount, the wrap price and both emails. The other posts an empty cart, to check that validation runs on the real request. Symfony logs that 422 as an exception before it becomes the response, so the test output shows an error line even though the test passes.

I did not add a real SMS provider, and I do not check that a mobile looks like a phone number. The number is not stored on the order. I would do both once there is a provider to send to. The order log is still a line appended to a file. A logger would be the next change if that line needed to go somewhere else.
